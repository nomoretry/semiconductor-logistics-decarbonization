# 多SKU与共享容量环境

研究问题：在承诺订单已知、海运扰动状态尚待确认时，如何分配有限查询预算，并将多个SKU分配到共享容量的运输路线。

## 实现

- 3或4个SKU，一条空运、两条海运；整数发货、SKU重量、交期、路线适配和路线总公斤容量。
- 两条海运各有正常/延误状态，公开联合先验覆盖4种情况；状态可相关。需求不随机，订单不随步骤增加。
- 两个精确路线确认工具、一个有噪声的网络状态工具；给定扰动状态，各查询回答条件独立。工具价格与回答似然均对策略公开。
- 查询共用预算并预留一次求解费用；每个信息源最多查询一次。工具顺序为查询、求解、提交，最多5步。它仍是短程开发环境，不宣称长链Agent能力。
- 求解时枚举所有可行整数分配；目标为运费、库存持有、积压罚项、排放价格、超碳预算罚项和查询/求解费之和。金额为仿真假设单位，查询费不代表API账单或实测计算耗时。
- 无查询Bayes、无查询稳健、熵收益/费用、一步VOI、两步前瞻和完整DP六种方法。除稳健选择外，所有方法共用同一精确期望物流分配求解器。

精确DP的状态只有查询回答历史；后验由公开先验和似然计算。环境私有扰动、预采样回答及任务ID不进入策略。被拒绝的工具调用不修改状态。计划提交后，另外重放每个SKU的到货、库存和积压，核对容量与费用。

## 开发结果

协议见[protocol.json](../coupled_decision/protocol.json)。120个开发情境分成4类，每类30个；6种方法共720条运行记录。它们没有充当最终测试集，也没有训练种子。

| 方法 | 平均期望总损失 | 逐情境归一化遗憾的均值 |
|---|---:|---:|
| 无查询Bayes分配 | 79.0440 | 17.0857% |
| 无查询稳健分配 | 83.3638 | 23.6994% |
| 熵收益/费用查询 | 70.0077 | 5.2882% |
| 一步VOI | 67.3328 | 0.002063% |
| 两步前瞻 | 67.3294 | 0% |
| 精确DP | 67.3294 | 0% |

归一化遗憾逐题计算为 `(方法期望损失 − 精确DP期望损失) / max(1, 精确DP期望损失)`，再求均值，不是表中均值的比值。期望枚举全部4种扰动及查询回答，实际单次运行的服务与排放另存，不能混用分母。

放宽共享运输容量在95.83%的情境降低最优损失；放宽查询预算和查询次数上限在16.67%的情境降低损失；提高查询价格在69.17%的情境改变首个动作。逐SKU单独分配在85%的情境超过共享容量；该诊断也去掉了全局超碳罚项，不作为公平主基线。

**耦合约束有实际后果，但当前规模仍不足以支持BC/PPO研究。** 两步前瞻达到精确参考，一步VOI也几乎无遗憾。精确DP必须继续作为基线。下一项实验应测量更多独立扰动与容量池下的质量—计算耗时关系，预先给出计算预算，再判断学习策略是否有价值；不能通过削弱基线或重复扩充同类任务制造收益。
