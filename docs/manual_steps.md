# 需要你操作的部分

代码、离线实验、测试和证据复算由研究仓库提供。现在需要你完成仓库合并、新任务的手动API运行，以及来源标签审核；不需要在本地安装Python，也不用重新发送API密钥。

## 1. 合并本轮PR

打开仓库的`Pull requests`，进入标题包含“真实数量抽取与查询规模审计”的PR。查看`Files changed`和检查结果；`Python offline checks`成功后，点击`Merge pull request` → `Confirm merge`。合并后新的手动工作流才会出现在main。

## 2. 运行新的8条真实数量评测

1. 打开仓库`Actions`。
2. 左侧选择 **Real fact extraction (manual)**。不要选择已完成的`Notice API evaluation`或`Real notice audit`。
3. 点击`Run workflow`，分支选`main`，`split`保持`exploratory`。
4. 再点绿色`Run workflow`，只运行一次；若显示Queued，先等它开始，不要重复创建任务。
5. 完成后打开`Summary`，检查`requested=8`、`completed=8`、`errors=0`，以及`metrics`、`frozen_rules`和`paired_completed`。工作流成功只说明运行和验证结束，不要求模型全部答对。
6. 把此次运行页面的链接发回对话。该链接含`/actions/runs/`。原始证据会保留为`notice-facts-exploratory-...` artifact，保留14天；我们据此归档、复算和解释结果。

这次沿用仓库已有`OPENAI_API_KEY` Secret，不需要编辑Secret。工作流是8次模型调用，总预留上限USD 0.05；当前按声明费率估计预留约USD 0.0081，实际账单以服务方为准。普通CI不调用模型。若失败，把运行链接发回即可，不要直接反复重跑；已发出的请求可能已计费。

## 3. 人工核对参考标签

打开[审核表](../reviews/notice_facts_v1/review.md)，先看上半部分的8条新材料。每条核对：

- 链接是否确为官方公告，摘录能否在该页找到。
- 数字描述的是运输总时长、延误、增加/减少时长或增加距离，还是停航、容量、日期等别的量。
- 单位、范围、平均/目标等限定语是否保留；答案是否增加了摘录没有给出的信息。

不需要会Python。按以下格式直接回复本对话，8条逐条填写即可：

```text
审核者：你的名字或固定代号
E01：同意；来源和摘录核对一致
E02：修改；原文是……，建议应为……
E03：不确定；页面打不开/语义有歧义……
```

请复制表中的实际案例ID。若愿意在GitHub保存，可点击审核表右上角铅笔，在每条的“人工意见”处填写，再点`Commit changes`，选择新分支并提出PR。只改审核表，不直接改冻结的`dataset.json`、规则或历史结果。

这是查看参考答案后的人工复核，不是盲标。无法判断可以填“不确定”；我们会保留分歧、单独记录裁定和修订版本，不把尚未审核的标签写成人工金标准。8条完成后可继续核对下半部分16条开发材料。若后续需要盲标，会另给不带参考答案的材料。

## 目前不需要的操作

不需要提供公司私有订单、客户清单或订舱记录，也不需要租GPU或启动BC/PPO。当前公开公告足以做来源数量抽取；未来验证真实内部路线更新时，才需要获得合法可用的路线映射、订舱/发运日期与更新规则。需求不确定性仍按既定顺序放在后续阶段。
