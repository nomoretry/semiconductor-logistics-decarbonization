# 查询策略 BC 开发实验

## 问题与已有依据

研究问题是：离线模仿精确查询规划器，能否用一次最终运输求解和少量神经网络前向计算，接近在线搜索的成本表现？这是计算摊销实验，学习对象是查询或停止的选择，运输方案仍由整数规划计算。

此前[预算实验](query_budget_results.md)中，13 次与 65 次每决策求解预算存在质量和计算量差异，但平均遗憾筛选没有通过。该结果和原门槛保持不变。本实验不声称通过原筛选，不启动 PPO；它单独测量学习替代在线搜索的可行性。依据是仓库已有的计算取舍，以及参考项目的动态候选 BC、公开策略输入、检查点重执行方法，见[框架对照](framework_comparison.md)。

## 固定设计

- 沿用 `scripts/audit_decision_scale.py` 的已知订单、独立二元路线扰动、共享海运容量和有价查询。不是未知需求模型，也不是企业实测参数。
- 4/8/12 SKU × 2/4/6 个路线状态。训练种子 1001–1008，验证种子 2001–2002，开发评估种子 3001–3004：72/18/36 个独立上下文。与此前 54 个上下文做内容去重检查。
- 同一上下文的所有历史状态属于同一 split；不把同一任务的分支拆入训练与评估。36 个评估上下文是本次开发检查，使用后不再作为未来正式留出集。
- 教师枚举所有预算合法的查询历史，精确 DP 给出每个合法动作的期望成本。成本与最优值相差不超过 1e-7 的动作均为正例，避免把同价动作误记为错误。
- 策略输入仅含公开订单、费用、先验、容量、已观察答案与剩余预算。不含任务 ID、种子、教师值、最优动作或未查询的真实状态。
- 共享候选评分器：固定特征、32 单元 tanh 隐层、masked softmax、多正例集合负对数似然；NumPy float64 与手写梯度、Adam。单个训练种子 17，80 epochs，batch 128，学习率 0.003。上下文等权；训练中只按验证集损失选择检查点。
- 比较：不查询、公开先验优先规则、未训练网络、BC、13 次预算两步搜索、65 次预算迭代 DP。每种策略从独立缓存开始。BC 与不查询方法只有最终提交时一次 MILP，教师生成和训练成本另列，不计作免费。
- 用完整概率树算期望物流成本、查询费用、相对精确 DP 的遗憾及每任务期望 MILP 次数；保存每个节点的输入摘要、候选概率、动作和最终方案。求解次数不等于墙钟加速比。

## 证据和解释

保存配置、任务、逐状态教师值、初始与所选检查点、逐 epoch 日志、逐任务轨迹和汇总。验证器重新生成任务、重算教师、重训 BC、从检查点重执行策略并复算指标。数据生成与评估代码共享，验证属于一致性与执行完整性检查，不是第二团队的独立复现。

本次不以成功阈值选择性发布结果；BC 比规则差也保留。这里只跑一个训练种子，不作统计显著性或 PPO 收益声明。下一步依据误差类型决定改进特征、增加训练数据或尝试策略优化；正式 1,000 题、5 种子、消融与未知需求仍未完成。

以上配置在本地首次运行前写入，与实现和结果在同一 PR 发布，不称为有外部时间证明的预注册。

## 运行前检查的数值修复

首次教师生成在训练情境 `12-6-1004` 中止：整数方案的物理成本为 420.45000000000005，HiGHS 含连续碳超额变量的目标为 420.44999899999993，两者相差 1.000000111e-6，刚好越过旧实现的绝对 1e-6 检查。关闭预处理求得目标 420.45。未删除该情境或改变划分。

新增 `query_policy/solver.py`，保持原 MILP 与最优状态要求，对目标一致性采用绝对 1e-6、相对 1e-10 容差；发布成本始终由整数方案重新计算，容量和数量约束仍严格检查。本实验所有教师、学习策略和搜索基线使用这一后端，旧程序与证据不变。修复发生在训练与开发评估之前。
