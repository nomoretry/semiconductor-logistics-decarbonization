# 真实事实抽取与内部更新分开评测

16条真实摘录的窄任务审核已经完成：固定模型、冻结规则和始终澄清基线均16/16与助手参考一致。原始API响应见[归档](../benchmark_results/real_notice_api/)，复算：

```bash
python -m scripts.verify_real_notice_archive
```

这组结果只回答“信息不足时是否拒绝直接更新”。下一版应直接检验文本中确实存在的字段，保持原始16条与原评分不变。

## 两层输出

| 层级 | 输入与输出 | 单独评测 |
|---|---|---|
| 来源事实 | 原文中的服务、方向、地点、生效日期、数量、单位、增加/减少、区间/平均/目标值、证据位置 | 字段精确匹配、单位与限定语匹配、证据支持率；漏抽与无依据新增分开 |
| 计划适用性 | 来源事实 + 显式服务/路线映射 + 订舱/发运日期 + 更新规则 | 可更新、无影响、需要澄清及下游计划差异 |

已有摘录中有5条数量正例、11条没有目标物流数量的对照。5条分别是增加航程、目标延误区间、额外航程时间区间、平均运输时间减少、运输时间减少区间。周编号或日期不是运输时长。这些仍为已看过的开发/探索材料，不能重新命名为独立测试。

例如R015只能从可见摘录抽取“东行、平均缩短14天”。摘录本身没有服务名；MECL出现在全文和标题中。只有给模型提供相同全文范围时才能评分服务名，不能把全文信息当成短摘录的隐藏答案。R014的7–14天必须保留区间，R009的4,000英里必须保留距离单位。

## 下版验收条件

1. 固定字段Schema、规则版本与提示词；公开每个标签的证据位置和人工审核状态。
2. 先用已有材料开发，再从未用于调参的来源收集测试文本；按同一事件与更新链分组，避免同公告改写跨集合。
3. 包含明确数量正例、无数量、范围、平均、否定、恢复、版本冲突；报告实际来源数与事件数，不靠重复摘录凑数。
4. 与始终空输出、冻结规则和固定模型比较；模型API完成率、格式错误与语义错误分别报告。
5. 真实公告与合成内部映射组成的任务明确标为混合案例。只有取得真实订舱映射才能宣称真实内部参数更新验证。

当前只完成协议和现有字段盘点，尚未完成新的字段抽取API评测或人工金标准。
