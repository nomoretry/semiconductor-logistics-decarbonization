# 共享容量与查询规划的规模审计

上一版120个情境中，两步前瞻与精确DP一致。本轮增加SKU和独立路线扰动，检查差距是否出现，以及规划要调用多少次求解器。实现见[Python审计](../scripts/audit_decision_scale.py)，证据见[18个任务与72条运行](../benchmark_results/decision_scale/)。

## 环境

| 项目 | 设置 |
|---|---|
| 开发网格 | 4、8、12个SKU × 2、4、6个海运路线扰动 × 2个生成种子 |
| 发货决策 | 整数件数；一条空运路线与多条海运路线；每个SKU必须完成数量分配 |
| 容量 | 各路线质量上限；前两条海运路线另共用起运处理容量 |
| 扰动 | 各海运路线独立二元延误，公开先验；普通到达第2期，延误到达第4期 |
| 查询 | 精确查询一条路线的状态；价格2、3或5，共用预算8，最多3次 |
| 目标 | 运费、提前到达持有、逾期成本、排放成本和碳预算超额惩罚 |
| 终止动作 | 在当前后验下运行SciPy/HiGHS整数规划，再提交发货分配 |

订单、容量、费用和先验都是合成假设，不是企业实测参数。模型输入不含评估用的真实扰动；查询回答后才把相应状态加入历史。精确DP枚举合法查询树，每个终点调用MILP。这里的“精确”针对这个有限开发模型与给定先验。

## 结果

先对每个任务计算各策略在全部可能查询回答下的期望总成本，再与精确DP比较。相对差距为 `(策略期望成本 − 精确DP期望成本) / max(1, 精确DP期望成本)`，下表是18个任务的等权均值和最大值；不是实际企业成本节约率。

| 方法 | 平均相对成本差距 | 最大相对成本差距 |
|---|---:|---:|
| 不查询，直接优化 | 130.1085% | 365.9525% |
| 单步VOI，收到回答后重规划 | 0.5378% | 4.5134% |
| 两步前瞻，收到回答后重规划 | 0.0811% | 0.8224% |
| 精确查询DP + MILP | 0% | 0% |

“两步前瞻”限制每次选动作时的预测深度，不限制整个任务只查询两次。所有方法使用同一MILP终止规划器。保存的逐步轨迹是每个任务按公开先验抽取的一次实际执行；期望成本另外对全部查询分支求和，不能用这一条抽样轨迹代替期望评分。

| 独立扰动数 | 单步VOI：根节点MILP次数中位数 | 两步前瞻 | 精确DP |
|---:|---:|---:|---:|
| 2 | 5 | 9 | 9 |
| 4 | 9 | 33 | 41 |
| 6 | 13 | 71 | 119 |

根节点计时用每种方法自己的空缓存，排除一次公共HiGHS启动预热。6个扰动时，本次机器上根节点墙钟中位数分别约0.019、0.099、0.168秒。计时只有一次运行，保存在`runtime.json`，不属于确定性身份校验，也不是完整任务耗时或同墙钟预算对照。

## 复算与结论

```bash
python -m semiconductor_logistics scale-audit --output artifacts/decision_scale
python -m semiconductor_logistics scale-audit --verify --output benchmark_results/decision_scale
```

校验器重新生成任务，重算全部策略的期望成本，验证查询合法性、预算、提交后的终止、SKU守恒、路线/共享池容量、物理成本和报告。数值结果按容差比较；允许不同求解器版本在并列最优发货方案中选择不同解。测试另用小规模发货穷举和独立查询树递归核对MILP与DP。

扩大规模后出现了非零差距，但两步前瞻仍很接近最优，精确规划也仍较快。当前证据不足以宣称需要BC/PPO。本轮未训练、未冻结最终测试集。下一项验收是预先设定相同MILP调用预算，比较可随时返回合法方案的规划方法与缓存/近似策略；同时覆盖更多开发情境。只有质量或计算收益有实际意义时才进入训练。
