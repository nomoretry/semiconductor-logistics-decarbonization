# 相同求解调用预算下的开发对照

## 研究问题与事前设置

上一轮18个规模任务中，两步前瞻的平均成本差距为0.0811%，但没有限制规划计算量。本轮先固定以下设计，再运行并解释结果。沿用[规模环境](decision_scale.md)的已知订单、独立路线扰动、整数发货、路线/共享池容量与查询费用；不改动旧实现、旧数据或人工审核标签。

| 项目 | 固定设置 |
|---|---|
| 开发任务 | 4/8/12个SKU × 2/4/6个扰动 × 生成种子31、47、61、73、89、101，共54个情境 |
| 与已有数据关系 | 前18个情境与上一轮同生成设置；其余36个新开发情境单独分层报告，全部不是最终测试集 |
| 每次决策计算预算 | 1、5、13、33、65次MILP；13是主分析预算，足以从空缓存求解当前状态与最多6条查询的两种答案 |
| 实际信息预算 | 沿用每任务预算8、最多3次查询；这是信息费用约束，不是计算预算 |
| 方法 | 按索引的一步VOI、按公开影响排序的一步VOI、两步前瞻、逐层加深的查询DP |
| 精确参考 | 在同样信息费用/查询数约束下的完整查询DP；仅用于评分，不向有限预算策略提供结果 |
| 记录 | 每个可达决策节点、概率、动作、求解台账、缓存身份、合法提交方案、任务期望成本及求解量 |

每个方法与预算组合从空缓存开始。策略只能访问公开业务参数、已经得到的查询回答，以及本次运行合法计算过的条件方案。缓存仅沿实际执行路径继承；评估时两个回答分支各复制父缓存，不共享另一分支计算结果。缓存命中不计新MILP；所有未命中均实际调用原求解器，不用预计算答案伪装限额内求解。

先求当前后验下的可提交方案，再尝试查询动作；只有查询两种回答及所需子搜索全部完成，才允许用这个候选值替换已有选择。未完成的搜索不用于估计收益，但已付出的求解次数仍计入预算，已算出的方案可以缓存。预算耗尽后返回已有选择。后续查询回答仍需在新决策节点接受同一上限。

排序规则只读取公开状态：用各SKU数量、路线延误成本差、先验不确定性和查询价格构造影响/费用分数；它不是学习模型。前瞻方法先完成一步评估，再优先加深一步估值较好的根动作；不删除一步看似无收益但可能有组合价值的动作。

## 指标与进入训练的条件

主指标仍是相对精确DP的期望总成本差距。先对同一任务配对比较，再分别报告全部54个情境、旧18个和新36个。记录均值、最大值、差距超过2%的情境比例、期望查询数、期望及最大路径MILP次数。完整枚举策略自身会到达的回答分支，不把一个抽样执行当成期望成绩。

MILP调用数是可复现的计算代理，单次求解难度不同，因此不是相同墙钟时间比较。墙钟只作诊断，分开保存，不据此宣称速度提升。每个决策节点都验证预算；另记录整条路径总求解数，避免只展示根节点。

本轮事先采用保守的开发筛选条件：在主预算13下，从四种公开方法中按平均成本选出的最强方法，仍需同时满足平均相对差距至少1%、至少20%情境差距达到2%；预算65下的最强方法还需让平均差距相对缩小至少20%，且所有方法所有已执行分支合法。仅预算1或5的退化不作为进入训练的依据。筛选分别检查全部情境与新36个情境，两者都通过才考虑BC可行性研究；这不是最终显著性检验，也不证明PPO必然获益。

未通过就保留负结果，继续使用优化/规则方案；不通过改测试分布、抬高难度或隐藏强基线制造学习优势。真实公告的E01–E08人工复核独立进行，合并代码不表示标签已经人工确认。
