## 中文

**怎样读。** 每格三个符号是同一题的第 1、2、3 次。“冻结”是官方成绩（模型 52/60，规则 6/60），“修正”是同一批保存的回答用修正评分器离线重评的结果（模型 54/60，规则 6/60），没有调用模型。A04 修复后的 3 次复测不在这张表里，单独报告。规则是确定性的，三次相同，实际只是 2/20 题通过，重复不是新的独立证据。所有区间按题计算。

**冻结的评分规则（`eval_v2.score_run`，事前提交）：**

| 类型 | 题目 | 成功条件 |
|---|---|---|
| scenario | A01–A07 | 必需工具都成功；某次成功的 `create_scenario` 与参考参数逐字段一致（周次和延误周数完全相同；运力、运费变化误差不超过 1 个百分点；距离系数误差不超过 0.01；按线路展开后比较，多出来的扰动算错）；回答含全部引擎数字；数字审查通过；没有错误 |
| tool | B01–B05 | 必需工具和关键参数；引擎数字；数字审查；没有错误 |
| refuse | B06 | 不调用工具，并且回答含拒绝词（`evaluate.REFUSAL`）；数字审查；没有错误 |
| clarify、notice | A08、C01–C06 | 回答有表示缺失或提问的字眼，并说到路线映射、周次、幅度中至少两类；如果仍建场景或求解，必须标为假设；数字审查；没有错误 |

**修正评分器 v2.1（`planning_agent/eval_followup.py`）只改三点：**

1. 所有文字规则之前先把弯引号统一成直引号。
2. 拒绝判断改为：有第一人称的“不能”或范围说明，并且回答没有实际照做。旧规则只看词表，会把 “You can't go wrong: your flight is booked.” 判为拒绝；新规则判为没有拒绝。这一点有正反两面的测试。
3. 线路范围直接读工具实际生成的结果，这样修复前后的运行用同一口径比较。

题目、参考数字、缺失信息规则都没有改，所以 C03 在修正评分下仍是 0/3。

**CSV 各列。** `task`、`group`、`kind`、`language`、`run`：题目信息。`model_frozen_success`、`model_corrected_success`、`rule_frozen_success`、`rule_corrected_success`：两种评分下的成败。`model_frozen_labels`：冻结评分的失败标签。`requests`、`tool_calls`、`seconds`：模型的请求数、工具调用数、运行秒数。`cost_usd_at_list_price`：按官方标价折算的费用，不是账单对账结果。`note`：A04、B06、C03 的说明。`question`：题目原文。

## English

**How to read it.** The three symbols in a cell are runs 1, 2 and 3 of the task. "Frozen" is the official score (model 52/60, rules 6/60). "Corrected" is the same saved answers rescored offline with the corrected scorer (model 54/60, rules 6/60); no model was called. The three A04 retest runs after the fix are not in this table and are reported separately. The rules are deterministic and their three repeats are identical, so they pass 2/20 tasks, and the repeats are not new independent evidence. All intervals are over tasks.

**Frozen scoring rules (`eval_v2.score_run`, committed in advance):**

| Kind | Tasks | Success requires |
|---|---|---|
| scenario | A01–A07 | Required tools succeed; one successful `create_scenario` matches the reference field by field (weeks and delay weeks exactly; capacity and rate changes within 1 percentage point; distance factor within 0.01; compared per lane, and extra disruptions count as wrong); the answer contains every engine number; numeric review passes; no error |
| tool | B01–B05 | Required tools and key arguments; engine numbers; numeric review; no error |
| refuse | B06 | Calls no tool and the answer contains a refusal word (`evaluate.REFUSAL`); numeric review; no error |
| clarify, notice | A08, C01–C06 | The answer has a word signalling a gap or a question and names at least two of route mapping, weeks and magnitude; if it still built a scenario or solved, it labels that as an assumption; numeric review; no error |

**Corrected scorer v2.1 (`planning_agent/eval_followup.py`) changes three things only:**

1. Typographic quotes become straight quotes before every text rule.
2. A refusal now means first-person inability or a statement of scope, in an answer that does not actually comply. The old word list would count "You can't go wrong: your flight is booked." as a refusal; the new rule does not. Tests cover both directions.
3. The lane scope is read from what the tool actually built, so runs before and after the fix are compared on the same terms.

Tasks, reference numbers and the missing-information rule do not change, so C03 stays 0/3 under the corrected scorer.

**CSV columns.** `task`, `group`, `kind`, `language`, `run`: the task. `model_frozen_success`, `model_corrected_success`, `rule_frozen_success`, `rule_corrected_success`: success under each scorer. `model_frozen_labels`: frozen failure labels. `requests`, `tool_calls`, `seconds`: the model's requests, tool calls and run time. `cost_usd_at_list_price`: cost at the official list price, not a reconciled invoice. `note`: remarks on A04, B06 and C03. `question`: the task text.
