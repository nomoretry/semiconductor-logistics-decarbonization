# Marvell-inspired：低碳fabless供应链物流与库存联合优化

本子项目研究已封装／测试可发货产品的跨区域补货、运输模式和区域仓库存。业务背景来自Marvell公开资料，**订单、SKU箱、价格、能力、仓库系数和运输提前期为明确标记的仿真假设，结果不是Marvell实际成本、经营预测或实际减排成效**。

实验日期为2026-10-30。第一版采用16周已承诺订单簿及已公告扰动的整数规划。所有策略看到相同订单簿，**本版不是未知需求下的随机滚动控制，也没有调度晶圆厂生产**。

## 1. 与ASML子项目的区别

Marvell公开披露其fabless模式及外包晶圆制造、封装与测试网络。本例因此采用两个独立的假设OSAT可发货池，服务一个假设新加坡区域仓：

| 假设供货池 | 运输选择 | 可供SKU箱 |
| --- | --- | --- |
| 台湾TW | `TW_air`空运；`TW_ocean`海运 | 交换芯片箱、网络控制器箱 |
| 马来西亚MY | `MY_air`空运；`MY_road`公路 | 存储控制器箱、定制芯片箱 |

每个SKU的来源资格固定，不能任意把台湾产品切换为马来西亚产品；同一来源的不同运输方式共享可发货释放能力，不能把两个模式的能力简单相加当成两份供给。箱是本实验的归一化订货单位，不是真实Marvell产品型号、包装规格或裸芯片数量。

本模型把制造释放量／可发货上限作为外生输入；不优化晶圆制造、良率、封装工艺和工厂能源。制造与产品隐含碳不计入可优化排放，货损也不考虑。因此讨论限于**物流减碳**。Marvell官网指出直接制造供应商占其上游GHG排放超过98%，本实验运输减排不能代表全公司减排。

## 2. 假设、公开来源与核算范围

完整配置见[config.json](config.json)。以下值均用于可复现实验，不能作为企业报价或运营参数引用。

| 参数 | 本例设置与来源性质 |
| --- | --- |
| 时间与订单 | 16周，4个SKU箱；10份合成订单簿，种子100–109；基础周均箱量为30、20、25、15，生成时含5%零订单概率，第9–10周加入相同的大单压力 |
| 箱重 | 1.5、2.0、1.2、2.5kg；假设的毛重 |
| 箱货值 | 15,000、22,000、18,000、30,000美元；假设值，用于资本占用成本 |
| 运费 | 空运5.5美元/kg，海运0.6美元/kg，公路0.7美元/kg；均为情景假设，非实际报价 |
| 提前期 | 台湾空运1周、海运3周；马来西亚空运和公路均1周；按周离散的情景假设 |
| 运输距离 | TPE–SIN约3,222.38km、KUL–SIN约297.47km为公开机场坐标推算的大圆距离；海运4,000km、公路400km为说明性假设，不是经核验的公司路线 |
| 常态能力 | 每条路线每周最多140箱；TW、MY来源各自每周最多释放160箱，跨本来源模式共享 |
| 库存与资本 | 年资本持有率20%；仓库费用0.4美元/箱周；仓库排放0.04kgCO₂e/箱周；均为独立假设系数 |
| 起点与期末 | 按4倍基础周均箱量设初始现货，且不低于首周已知订单；同一订单簿所有策略使用相同初始库存、零初始在途；每个SKU期末库存至少恢复至其初始库存，阻止靠耗尽期末库存制造虚假收益 |

运输排放使用英国DESNZ2026公开平均因子作为**情景代理**，并非台湾／马来西亚航司、船公司或车辆的实测因子：

| 模式 | 本例合并因子，kgCO₂e/吨公里 | 边界 |
| --- | ---: | --- |
| 空运 | 0.66646 | 不含航空间接非CO₂气候效应的运营排放＋燃料WTT |
| 集装箱船 | 0.01977 | 平均集装箱船运营排放＋燃料WTT |
| 柴油公路货运 | 0.12715 | 英国平均非冷藏重货车运营排放＋燃料WTT |

按`发运箱量×毛重kg/1000×距离km×因子`计算运输排放；仓库排放按各期现货库存另计。WTT只加一次。所选航空因子已经包含其官方距离增量处理，不再额外把大圆距离乘以1.08。短程KUL–SIN使用国际平均航空因子只是代理，应在后续采用当地或承运人参数检验。

来源表、原表行号、单位和RF敏感性口径见[排放因子记录](../data_sources/selected_emission_factors.json)；机场数据来源见[airport_coordinates.json](../data_sources/airport_coordinates.json)。企业及相似业务的数据检索、适用性与许可边界见[Marvell数据审查](../data_sources/data_audit_marvell.md)。本例没有将财务库存天数解释为运输时间，也没有伪造企业私有SKU记录。

## 3. 优化模型与比较方式

整数决策为各期、路线和合格SKU的发运箱数。模型逐期追踪到货和库存，限制每条路线能力以及跨模式共享的来源释放能力。任何周末都不允许积压，即所有已承诺当周需求均须在该周结束前满足；这是一项周粒度服务约束，不表示日内零等待。

费用由运费、在途资本占用及仓库现货持有成本组成。固定需求下不另行优化采购总量的价格，也没有把固定制造排放计作可节省排放。

比较6个策略／限制：

1. `cost_only`：在相同服务约束下最小化费用。
2. `fast_only`：限制为空运，再优化发运与库存。
3. `slow_only`：仅使用海运／公路，再优化发运与库存。
4. `carbon_minus10`、`carbon_minus25`、`carbon_minus50`：将总物流排放上限分别设为**同一订单簿、同一扰动场景**的`cost_only`排放的90%、75%、50%，然后最小化费用。

不是用“只空运”作为唯一减排参照。费用优化本身也会选用部分低碳运输，进一步降低碳预算的费用代价应相对这个更强的参照计算。限制与需求无法兼容时，保留不可行记录，不把它记为零费用或零排放。

3个主场景分别是常态、运输延误、路线运力限制。延误场景的名称为`ocean_delay`，但本Marvell例实际同时包含第5–9周台湾海运和马来西亚公路各增加1周的公告；运力场景在第7–9周将TW空运降至12箱/周、MY公路降至10箱/周。其他来源和路线的限制保留原设置。

## 4. 已运行结果

Marvell主网格共`3场景×10订单簿×6策略=180`次求解；177次得到求解器的可行最优状态（设置相对MIP gap容差为`1e-4`），3次为仅使用低速模式的不可行实例。下表的两种策略在每一场景均10/10可行，因而比较的是完全相同的订单簿集合。费用是16周合计的假设美元费用，排放是16周物流kgCO₂e；每行先对10个种子取均值。

| 场景 | 仅费用最优：费用 | 减碳25%：费用 | 费用增加，均值之比 | 仅费用最优：kgCO₂e | 减碳25%：kgCO₂e | 两种策略可行数 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 常态 | 207,267.72 | 230,273.61 | 11.10% | 3,231.99 | 2,423.46 | 10/10；10/10 |
| 海运／公路延误 | 209,207.07 | 232,736.14 | 11.25% | 3,291.54 | 2,468.11 | 10/10；10/10 |
| 路线运力限制 | 226,634.53 | 243,852.11 | 7.60% | 2,811.44 | 2,107.86 | 10/10；10/10 |

每一对都满足相同的100%周末需求约束和期末库存要求。常态下，减碳25%使空运质量份额从约56.13%降至41.37%；平均现货库存由63.675箱降至58.25箱，但在途资本占用费用上升。它说明运输速度、物资价值、补货节奏和库存位置存在联合取舍，不能预先断定低碳方案必然增加所有类型库存。

这些费用数值由合成订单与假设货值、费率主导，不能据此预测Marvell节约或支出多少美元。排放下降约25%是显式碳上限的结果；需要研究的是在相同服务条件下该上限是否可行、费用代价和模式组合如何改变。

原始记录见[episodes.json](../reports/episodes.json)、[汇总summary.json](../reports/summary.json)、[订单簿与场景instances.json](../reports/instances.json)以及[逐期计划plans.json](../reports/plans.json)。这些共享文件可按`project=marvell`筛选。不可行实例没有混入可行实例的费用均值。

公开逐次结果、实例及计划明细仅含`demand_set=synthetic_weekly`；Marvell子目录分别有180条求解记录、30份合成实例和177份可行计划。共享汇总、运行清单及报告覆盖原400次实验，包含ASML外部汽车备件压力测试的聚合统计；公开明细不包含外部实测需求序列、选中序列ID或逐实例结果。首次下载数据后运行`--project both`可在本地重现完整实验。

## 5. LLM信息处理试点与实际局限

试点共12条合成业务通知，其中Marvell有6条：运输延误、路线能力、来源共享释放量、碳预算、运费变化及一条关键信息缺失的通知。会话内ChatGPT-agent进行了一次抽取，输出保存为JSON，随后由允许列表编译器更新模型参数；没有执行模型生成的代码，也没有调用外部API。

Marvell的6/6条保存结构与参考标签一致，其中信息不足的M06要求澄清。数值试点只对M01延误、M02路线能力两类公告分别重放10份订单簿，即每种信息处理方法20个Marvell实例：

| 输入处理方法 | 能在自身规划模型中求解 | 在更新后的真实情景重放，满足全部约束 |
| --- | --- | --- |
| 正确结构化输入＋同一优化器 | 20/20 | 20/20 |
| 保存的LLM抽取结果＋同一优化器 | 20/20 | 20/20 |
| 忽略公告，按旧参数规划 | 20/20 | 0/20 |

忽略公告的计划在旧信息下看似可行，延误案例重放产生积压，运力限制案例则出现不可执行发运。不能把旧参数模型的求解成功误称为实际方案可行。

保存的LLM抽取与正确结构化输入产生相同参数，因此结果相同。本试点体现的是信息处理自动化的潜在价值，**没有证明LLM胜过优化器，也没有证明其可在真实未见通知上稳定泛化**。样本很小、模板化且没有独立留出的提示词／模型比较，未计量token、时延或API费用。数值重放可复现，重新生成LLM响应需要新的模型会话。

参阅[通知文本](../llm/notices.json)、[抽取提示](../llm/extraction_prompt.txt)、[保存输出](../llm/extracted_notices.json)、[参考结构](../llm/reference_labels.json)和[notice_pilot.json](../reports/notice_pilot.json)。M03–M05目前只验证结构抽取，没有在本次20实例试点中逐项开展优化重放。

## 6. 运行命令

在完整项目根目录运行，本子目录依赖共享优化器、数据源与脚本：

```bash
python -m pip install -r requirements.txt
python scripts/download_source_data.py
python -m unittest discover -s tests -v

# 只运行Marvell的180次主实验
python scripts/run_experiments.py --project marvell

# 更快的单种子检查
python scripts/run_experiments.py --project marvell --smoke

# 重放Marvell保存的通知抽取结果
python scripts/evaluate_notice_pilot.py --project marvell
```

研究记录中的10个种子用于生成不同的已承诺订单簿，而不是为相同确定性计划制造重复样本。若重新只跑一个子项目，输出文件可能更新为该次运行的范围；保留原始报告副本以便核对。

## 7. 后续需要检验什么

- 将已承诺订单扩展为逐期可见需求与未知扰动，比较滚动优化、库存规则和学习策略，避免将本版全订单簿规划结论直接外推。
- 增加独立、自然写法及多语言业务通知，加入明确的拒答／澄清条件，测量抽取错误造成的费用、服务和碳预算损失。
- 用授权的SKU需求、释放量、在途和运价数据替换假设，并检验资本持有率、路线距离及承运人排放因子的敏感性。
- 只有当实际改变制造／采购数量或报废数量并建立相应生命周期核算后，才扩展制造隐含碳；本版物流核算不承担该结论。
